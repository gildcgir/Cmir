# Smir — сценарии использования (use-cases)

Актёры: **Гость**, **Зарегистрированный пользователь**, **Администратор**, **Персонал перфоманса**.

---

## UC-01. Гость смотрит карту и превью места

1. Открывает главную → видит карту POI.
2. Нажимает на маркер → панель с адресом и live-превью.
3. Незарегистрированные лица в кадре — с маской (плашка); лицо не «светится» до маски.
4. После готовности — зацикленный клип **10 с** с эфира.
5. Может открыть трансляцию на весь экран.

**Ожидание (как у live-map продуктов):** карта → карточка места → превью → fullscreen.

---

## UC-02. Регистрация согласия в киоске

1. Гость подходит к киоску / открывает «Киоск согласия».
2. Видит камеру с маской на незарегистрированных.
3. Заполняет ФИО, телефон, любимое меню; читает и отмечает все юр. документы.
4. Нажимает «Регистрация и начало веселья!».
5. Система сохраняет биометрию (embedding), открывает кошелёк, выдаёт сессию.
6. **Новый аккаунт:** показывается телефон + **временный пароль** для входа позже.
7. Форма блокируется; маска на этом лице снимается (подпись с именем).

**Ожидание (consent-kiosk / venue biometrics):** согласие → шаблон лица → снятие privacy-маски; повторная регистрация того же лица недоступна.

---

## UC-03. Повторный визит к киоску

| Условие | Поведение |
|---------|-----------|
| Уже вошёл в аккаунт с активным согласием | Киоск заблокирован, кнопка недоступна |
| Распознано зарегистрированное лицо | Киоск блокируется: «вы уже зарегистрированы» |
| Согласие отозвано | Киоск снова доступен |

На главной ссылка «Киоск согласия» **скрыта**, пока есть активное согласие.

---

## UC-04. Вход в аккаунт

1. Аккаунт → «Вход».
2. Вводит **email или телефон** и пароль.
3. После киоска: телефон + временный пароль из UC-02.
4. Видит профиль, кошелёк (ST/UT), согласия, платформы.

**Ожидание:** один аккаунт на человека; вход тем же идентификатором, что при регистрации.

---

## UC-05. Просмотр после согласия

1. Открывает POI на карте.
2. Своё лицо — **без маски**, под головой **подпись имени**.
3. Чужие незарегистрированные — с маской.
4. Подпись привязана к **человеку (биометрии)**, не к конкретному POI: на любой камере, где лицо совпало.

---

## UC-06. Отзыв согласия (privacy)

1. Аккаунт → список активных согласий → «Отозвать».
2. Embedding удаляется из индекса; маска снова накладывается.
3. Ссылка на киоск снова появляется.
4. Можно заново пройти UC-02.

**Ожидание (GDPR / PDPL):** отзыв согласия → немедленное возвращение privacy-маски.

---

## UC-07. Перфоманс

1. Открывает «Перфоманс» у места с камерой role=performance.
2. Регистрация как в киоске (лицо + документы) **или** уже вошедший пользователь.
3. Управление эфиром: старт / стоп / сохранение клипа.
4. Подпись не «привязывается к общему плану» — она глобальна по лицу (UC-05).

---

## UC-08. Администратор

1. Вход admin / admin → админ-панель.
2. CRUD POI и камер (general / consent / performance), USB, маска, health.
3. Статистика: кошельки, топ мест по consent rate.

---

## UC-09. Выход

1. «Выйти» → сессия сбрасывается.
2. Киоск снова виден в навигации для гостя без токена; при следующем входе с активным согласием ссылка снова скрывается.

---

## UC-10. Присутствие в кадре и UT после эфира (Phase 2)

1. Зарегистрированный пользователь появляется на камере → система копит **секунды** `(user, camera)`.
2. По окончании эфира берётся длительность стрима `T` и время каждого участника `t_i`.
3. **1 UT = полный стрим.** Начисление: `ut_i = min(1, t_i / T)` автоматически на кошелёк.
4. Админ ничего не подтверждает; повторный stop не начисляет повторно.
5. В аккаунте видны накопленные секунды.

**Ожидание:** доля от 1 UT пропорциональна времени в кадре.

---

## Соответствие стандартной логике

| Практика | Smir |
|----------|------|
| Privacy by default (маска до согласия) | Да |
| Consent → unmask / label | Да |
| Revoke → remask | Да (API + UI) |
| Identity = person, not venue stream | Да |
| Kiosk не дублирует уже согласившихся | Да |
| Повторный вход после kiosk | Телефон + временный пароль |
| Preview clip после live | 10 с loop |

**Вне текущего MVP / в работе Phase 2:** scene narrator, ONNX embeddings, staff goals, load test, PostgreSQL.  
**Phase 2 (сделано):** face presence + доля от 1 UT пропорционально времени в кадре после эфира.
