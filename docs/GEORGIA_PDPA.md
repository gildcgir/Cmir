# Соответствие требованиям Грузии по персональным и биометрическим данным

Документ описывает архитектуру обработки данных в Cmir и меры, реализованные в коде (версия `1.0.0-ge`).

## Нормативная база

- Закон Грузии «О защите персональных данных» (PDPL)
- Подзаконные акты Персонального уполномоченного по защите персональных данных Грузии
- Специальный режим для **биометрических данных** как чувствительной категории

## Категории данных

| Категория | Примеры | Правовое основание |
|-----------|---------|-------------------|
| Идентификационные | ФИО, телефон | Явное согласие + договор (киоск) |
| Биометрические | Вектор лица (embedding 32×32) | Отдельное согласие на биометрию |
| Поведенческие | Время в кадре, просмотры | Согласие + легитимный интерес платформы |
| Финансовые | Электронный кошелёк ST/UT | Договор об открытии кошелька |

## Принципы обработки (PDPL)

1. **Законность и прозрачность** — киоск показывает 5 документов с индивидуальными чекбоксами «Согласен».
2. **Минимизация** — сохраняется только нормализованный вектор лица, не исходное видео регистрации.
3. **Ограничение цели** — биометрия используется только для снятия маски у согласившихся на данном POI.
4. **Ограничение хранения** — до отзыва согласия пользователем.
5. **Целостность и конфиденциальность** — шифрование embedding в `consents.face_embedding` (Fernet, ключ `CMIR_DATA_KEY`).

## Хранение в системе

- `users` — учётная запись (email-алиас от телефона для киоска)
- `user_profiles` — ФИО, телефон, любимое блюдо
- `consents` — согласие, зашифрованный embedding, версия документов
- `poi_embeddings` — операционный индекс для face-worker
- `consent_document_acceptances` — фиксация каждого из 5 документов
- `audit_log` — журнал действий
- `blockchain_records` — запись о регистрации (заглушка реестра)
- `legal_documents` — версионированные тексты в `data/legal/`

## Поток регистрации на киоске

1. Посетитель видит замаскированный HLS-поток с камеры согласия.
2. Заполняет ФИО, телефон, выбирает пункт меню.
3. Ознакомляется с 5 документами и отмечает все чекбоксы.
4. `POST /api/v1/pois/{id}/kiosk-register` — сохранение PII, биометрии, кошелька, audit, blockchain.
5. Face-worker подгружает embeddings и снимает маску при совпадении.

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/api/v1/legal/documents` | Тексты и версии документов |
| GET | `/api/v1/pois/{id}/menu-items` | Пункты меню заведения |
| GET | `/api/v1/pois/{id}/kiosk-stream` | HLS с маской для киоска |
| POST | `/api/v1/pois/{id}/kiosk-register` | Полная регистрация |
